CHANGES-NEEDED

1. **BLOCKING** — `os/input-portal/src/portal.rs:1142`, `os/input-portal/src/wayland/state.rs:378`. A queued crossing identifies its session by a reusable object path and barrier ID. If a session closes before the portal handles its crossing, teardown sends only `Disarm` because the activation ID is still zero. The Wayland capture retains its layer and buffered keys. A replacement session using the same path and barrier ID can then pass the old crossing check and receive those keys on its own EIS socket. Give each arming and crossing a unique token, check it when attaching EIS, and make disarming the owner discard its pending capture and input.

2. **BLOCKING** — `os/input-portal/src/portal.rs:1817`. If the backend loses its bus connection, the frontend watch can end without a final owner-change signal. The watcher only logs and returns, so a surviving Wayland connection and Deskflow EIS socket can still capture at the next crossing, while the bus can no longer deliver `Close` or `--disarm`. Treat the end of the watch as frontend loss and tear down all sessions before exiting the backend.

3. **BLOCKING** — `os/input-portal/src/wayland/state.rs:371`. The backend announces activation when it requests the lock. The compositor's `locked` callback at line 847 only logs. If the compositor delays or declines the constraint, Deskflow can report an active remote screen while a click still lands in a local window. Keep the crossing pending until the matching lock is confirmed and the barrier has keyboard focus for a keyboard grant. If acquisition fails or times out, restore local input and discard the pending events.

4. **SHOULD-FIX** — `os/input-portal/src/portal.rs:1336`. The signal emitter has no D-Bus destination. An unrelated subscriber on the session bus receives the exact cursor position on `Activated` and clipboard types and transfer serials on clipboard signals, even though its method calls would be refused. Address these signals to the creating frontend's unique bus name and verify that a second bus connection receives none of them.

5. **SHOULD-FIX** — `os/input-portal/src/wayland/state.rs:616`, `os/input-portal/src/wayland/state.rs:695`. Closing the active layer or losing the pointer capability releases the grab without reporting `CaptureLost`. With the output still present, no screen change has to follow, so the frontend can still regard Deskflow as active and grant it reads of clipboard content copied after control returned locally. Report the loss of the matching capture through the same path as an unlock, so EIS stops and the frontend receives `Deactivated`.

6. **SHOULD-FIX** — `os/input-portal/src/portal.rs:975`. A clipboard read checks the session, queues a Wayland request with only the MIME type, and returns the resulting descriptor without checking the session again. If teardown completes while the request is waiting, the old session can receive a pipe for a selection copied after it closed. Bind the pending read to that session instance and drop the descriptor if teardown won the race.

7. **SHOULD-FIX** — `os/input-portal/src/main.rs:48`. The production filter admits dependency warnings. The pinned Smithay client toolkit formats the entire pointer event kind in its `sctk` warning for an event received without an entered surface, so a scroll in that error path writes its axis values to the log. Suppress that payload-bearing diagnostic and test the production filter with a marked scroll value through the dependency's logging path.

8. **SHOULD-FIX** — `os/input-portal/src/wayland/mod.rs:301`. The outer-edge check detects adjacent outputs only when their boundaries coincide. If one output extends from x=0 to 1920 and another from x=1600 to 3520 across the same rows, the first output's right edge is inside the desktop, yet the backend accepts a barrier there and can send local input to Deskflow. Reject a barrier whenever another zone covers the pixels immediately beyond its proposed edge, including partially overlapping layouts.

9. **NIT** — `os/input-portal/src/eis_server.rs:158`, `os/input-portal/src/eis_server.rs:546`. A receiver binding only relative motion gets button and scroll interfaces too, and a later narrower bind keeps previously requested devices. This stays within the portal grant, so the effect is extra events for an already authorized receiver. Keep the actual bound capability mask and update the devices when that mask changes.
