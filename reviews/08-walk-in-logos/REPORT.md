# 08: Walk-in app logos

PR: [#7](https://github.com/carlsenares/AresOS/pull/7) against `main`.
Branch: `pkg/08-walk-in-logos`. Not merged.

**Done:**

- `zone/AppZone`, `ZoneData`, `WalkInZones`: dimension-specific boxes, app IDs,
  exact exits and auto-built block positions in `data/aresos/zones.dat`. Zones
  reject overlap and exits touching another zone. Live host body entry launches
  once, with portal particles and a short teleport sound. Build, normal worlds,
  rejoin-inside and mode-switch-inside do not launch. Session-unique visit IDs
  keep old cancellations/returns from affecting newer launches after resets.
- `zone/ZoneCommands`, `LogoBuilder`, `LogoPixels`: host-only, cheat-free zone
  commands and automatic wall/floor construction. Source icons fit within 32×32
  without upscaling; area sampling preserves alpha and a fixed palette maps RGB
  to 48 concrete/wool/terracotta blocks. Transparent pixels place nothing. The
  entire face and approach are checked before writing; occupied cells, entities,
  overlap, unsafe exits and world limits are refused. No overwrite path exists.
  Player breaking of auto-built positions is blocked in Live and allowed in Build.
- `AresOsClient`, `FocusReturn`, focus mixin and two payloads: use the existing
  launcher for programs and URLs. Owned focus return sends a matching visit back
  to the server, including with pause-on-focus-loss disabled, then teleports to
  the saved safe exit facing the zone. Failure cancels only its own launch;
  obstructed exits refuse teleportation. Client launch packets also require a
  local AresOS world in Live mode, preventing remote-server automatic launches.
- Tests: a frozen 32×32 compass block golden, alpha/aspect/palette checks, focus
  token checks, two server game tests, and a client test covering commands,
  movement, return, persistence, protection, failure and state-reset races.
  `mod/README.md` documents the commands, geometry, save data and refusal behavior.

**JUDGMENT-CALL:**

- **Placement and entry:** four blocks ahead along the nearest cardinal direction;
  walls rise from the feet, floors sit one block below them. Wall approach is two
  cells deep, and floor approach is two cells high. Entry uses the player's body
  intersecting the box, so transparent floor borders do not require a precise
  feet position. Exits must clear a full standing body. Building at the player's
  feet or using a three-cell offset risks enclosing the saved return position;
  feet-only detection is brittle over holes. Changing these defaults affects
  newly created zones only; existing zones can be removed/recreated.
- **Exit selection:** owner-built zones save where the owner stands for `zone set`,
  looking toward the zone centre. Auto-built zones save where the owner stands
  for `logo`. The alternative was searching nearby terrain automatically, which
  can choose a surprising return location. If that exit later becomes unsafe,
  return is refused with a message rather than moving blocks or risking
  suffocation. A separate exit-edit command would be a later, reversible addition.
- **Overwrite policy:** refuse every occupied face/approach and tell the owner to
  clear it manually in Build mode. The brief permits refusal; no confirmation or
  destructive overwrite syntax was added. A future preview/confirmation command
  can be added without changing existing world data.
- **Icons and palette:** cap original sources at 32×32, keep smaller sources at
  native size, use area-weighted RGB/alpha and a 50% visible-alpha threshold. Use
  a fixed numeric 48-color palette and squared RGB distance with stable ties.
  Larger art is harder to place; always using the 16×16 item cache loses source
  detail. Future palette/style changes alter only new builds and require explicit
  review of the golden and screenshots; existing blocks stay in the save.
- **Scope and removal:** only the singleplayer host auto-launches, including on a
  LAN-open world; guests cannot edit zones. Several zones may launch one app.
  Removing by app ID removes every matching zone in every dimension; `here`
  removes touching zones. Blocks remain and lose zone protection. Automatically
  deleting their blocks could destroy later owner edits; guest launching would
  need a separate per-client catalogue/authority design.

**PLAN-GAP:**

- An app can have no usable source icon (URLs commonly have none; existing
  discovery may also fail). The builder refuses with instructions to configure a
  local PNG instead of fetching a favicon or inventing an icon. Owner-built zones
  still work for those apps. This stays within the catalogue's existing offline
  behavior.

## 08b: Walk-in review fixes

**Done:**

- `WalkInZones`: records the complete set of body-intersected zone IDs on every
  tick. Each zone consumes its launch attempt on its own entry edge and rearms
  only after a real exit. Failed/refused launches, Build movement and initial
  membership keep the same suppression behavior. Crossing an adjacent seam no
  longer makes an occupied zone appear newly entered.
- `LogoBuilder`: checks a two-step neighbor margin before the first write. Air
  and plain inert full blocks are safe; fluids and blocks with special behavior
  are refused with their block ID and position. This deliberately avoids placing
  and rolling back blocks after survival updates, redstone or drops have fired.
- `AppZone` / `ZoneData`: share full standing-body geometry for exits and check
  actual planned logo pixels against saved exits, in both directions and against
  the new logo's own exit. Existing trigger-overlap and trigger/exit checks remain.
- `FocusReturn`: a valid launch owns its return token even when inventory or
  another screen was opened before focus loss. Closing a pause screen still
  requires ownership of that exact screen. Expired/cancelled launches cannot return.
- `LogoExplosionMixin`: removes saved logo positions from the real server
  explosion's block-destruction list in marked AresOS worlds, in both modes.
  Ordinary blocks still explode, and Build players can still mine logo blocks.
  No world-data schema or dependency versions changed. `mod/README.md` documents
  the new refusal and return behavior.
- Added four server regressions, one client regression class with independent
  seam/focus checks, and focused token unit coverage. The earlier builder test
  moves its fixture two cells inward so its safety margin clears the chamber's
  barrier walls; every existing assertion remains.

**JUDGMENT-CALL:**

- **Conservative neighbor refusal:** only air and unmodified plain `Block` full
  cubes without fluids, random ticks, signals or block entities are accepted
  within Manhattan distance two of a planned pixel. This includes ordinary stone
  and inert palette blocks, but can also refuse harmless slabs, logs, glass or netherrack.
  The alternatives were a growing special-block allowlist or speculative world
  simulation/rollback; both risk missing indirect support/redstone side effects.
  The brief explicitly prefers refusal when unsure. Relaxing this later is a
  local preflight change with no migration or changes to already-built logos.
- **Simultaneous new entries:** if the body enters two zones in the same tick,
  consume both entry edges, launch neither and explain how to step out and retry.
  Picking by saved-list order is arbitrary; launching both overwrites focus/return
  ownership. Entering a new neighbor while still occupying another zone remains
  valid. Changing the refusal policy is local runtime logic with no save impact.
- Explosion immunity applies in Build as well as Live, as required by 08b;
  player mining remains the explicit Build editing gesture.

**PLAN-GAP:**

No new blocker. Arbitrary neighbor behavior cannot safely be proved by a
write-and-undo check; the documented conservative refusal is the chosen safe
fallback. The prior package's icon-source limitation remains unchanged.
