**run [R]** Each ordinary held case waits at least 600 ms and inspects the independent server log before deciding. Release is single-use; changed preview hashes and repeated decisions fail. Receiver arrivals and pause/observation/decision records include monotonic timestamps; each held HTTP arrival is asserted to follow its decision. After all browser sessions, `delivery-audit.json` rechecks all 84 regular fixture cases for late/duplicate arrivals (disconnect probes are recorded separately) and compares released address/method/body against the preview. Each `*-holds.json` record gives the case ID, zero-arrival observation, exact preview and server arrivals; find the same ID in `server.jsonl`. These are fixture delivery guarantees over the observed run, not internet exactly-once semantics or a retry guarantee after an uncertain remote response.

**run [R]** The preview shows destination origin, complete URL/query, method, body and resource type. The tested text bodies, search parameters and ping payload are available. Upload bytes are known from the explicit file operation; arbitrary streaming/multipart bodies are not qualified. Waiting does not imply honest page UI: a beacon already looks queued, and a WebSocket shim can let the site claim “sent” while the receiver has nothing. Pending document navigation can queue `Runtime.evaluate`; the check keeps an explicitly cached view and report-only screenshots rather than inventing a fresh page read (`*-while-*-held.png`).

**run [R]** On each route, new-document wrapping held a cooperative WebSocket send with 0 arrivals, released one, and dropped another with 0. Installing the preload did not affect the already-loaded document; an existing socket still sent. A worker-created WebSocket bypassed the new-document shim. Withholding Enter instead gave 0 arrivals until the test approved dispatch, then exactly 1 (`ws-*` cases). [Network's WebSocket events](https://chromedevtools.github.io/devtools-protocol/tot/Network/) observe frames; the tested Fetch gate did not stop them. This is not a dependable generic WebSocket security shim.

**run [R]** Closing each tested controller released its deliberately pending POST without approval (`*-disconnect.json`). The minimal native extension explicitly detaches on native-port loss; keeping the debugger and aborting pending requests in the extension could fix that particular path. Uncontrolled detach/crash behavior is not thereby solved. A product cannot rely only on an in-memory pause in an external controller for fail-closed approval.

### Classifier and public sites

**run [R]** The candidate rule flags non-GET/HEAD/OPTIONS methods, Ping/report resources, declared form submissions (including GET), XHR/Fetch during typing, and query-bearing document requests. The fixture gate separately holds every `/receive` request; therefore HTTP interception success does not conceal classifier misses. The image GET proves a missed user-data send. An exact trusted destination origin was also exercised: its synthetic POST arrived once without entering the held set.

**run [R]** Public visits used no accounts. Wikipedia's synthetic search and Selenium's synthetic form were aborted at the request gate; BBC was only read. An independent guard also dropped Fetch/XHR/Ping requests that the classifier called reads. Requests are attributed to their source document, so late unload traffic does not become the next site's analytics. The final public experiment uses Playwright's request lifecycle (`playwright-public-sites.json`, full `playwright-public-traffic.json`). The raw native prototype hit unpaired/stale Fetch handles on live-site navigation ([run 42336435078](https://github.com/Ares-Empire/AresOS/actions/runs/42336435078), `PUBLIC_CHECK_FAILED`, `Invalid InterceptionId`); it is not qualified for that workload. Fixture assertions remain unchanged. Public observations were:

|---|---:|---:|---:|---:|
| **run [R]** wikipedia | 27 | 1 / 1 | 1 | 0 |
| **run [R]** news | 84 | 1 / 1 | 0 | 3 |
| **run [R]** demo-form | 7 | 0 / 0 | 1 | 0 |

**run [R]** These are short observations with deliberately blocked traffic, not a representative false-positive rate. Background candidate alarms are false alarms relative to an intentional form/typing send. Guard-only drops are not all proven mutations: they include reads/content APIs as well as possible telemetry. Public-site request counts vary between runs. The classifier misses the synthetic pixel despite the low short-run alarm count.

**assumed — hold rule recommendation.** Do not release an unknown request solely because it is GET, a resource load or outside a short action window. Require an immutable sending operation and approval before a known trigger; autosaving field edits themselves become sending operations. Combine qualified HTTP interception with per-site knowledge, explicit destination trust rules, and refusal where payload/cause/target cannot be established. Existing WebSockets, worker traffic, delayed/background sends, data-bearing links/resources and detach need an enforcement design beyond this heuristic. Holding Enter/click is reliable for the demonstrated trigger, not for arbitrary JavaScript running independently of it.

The check's installation/consent UI automation is not a Wayland implementation.

## Recommendation

**assumed — recommendation.** Choose the custom MV3/native-messaging route for a deliberately selected existing tab, with a protected broker and no raw CDP/evaluate escape in free tools. Adopt compact aria-like structure with browser-derived states and frame geometry; the measured Playwright AI format is a useful starting point. Use one owner of request interception. HTTP pauses are useful but insufficient as the approval boundary. For known chat/autosave workflows, hold the triggering operation before touching the page and show the exact qualified data; unknown channels remain unsupported until a reliable gate or owner trust exception is available. The owner does one installation/provisioning step, then explicitly shares a tab per connection; Claude Code's eventual `chrome_submit` prompt is a later enforcement task, not implemented here.

## Risks and PLAN-GAPs

- **run [R] / PLAN-GAP:** “A click or key that sends becomes a separate submit automatically” is not established for arbitrary sites. Worker/WebSocket/pixel counterexamples defeat the tested generic divider.
- **run [R] / PLAN-GAP:** Debugger detachment released held data. A design needs a fail-closed lifecycle, not merely a happy-path permission prompt.
- **run [R] / PLAN-GAP:** Raw automation channels are broad authority. Same-UID spoofing/reuse succeeded in the tested native/Playwright transports; tab selection is not an OS security boundary.
- **run [R] / PLAN-GAP:** The consent route opens a TCP listener despite using no launch switch, conflicting with the owner's prohibition. Its connection approval is not per-action approval.
- **assumed — design gap:** Free navigation/links/resources and “anything that sends data asks” need a precise policy: a path/query/image can encode data, and GET can have effects. A short causal window cannot prove that background traffic is harmless.
- **assumed — deployment risk:** Signed CRX identity, policy updates, actual profile permissions, extension conflicts and Chrome upgrades need image-level regression tests. The pinned Web Store download intentionally fails integrity/version checks if the store replaces it; archival availability is not guaranteed.

## JUDGMENT-CALL

- **assumed — owner-facing choice:** Explicitly share one tab per connection; reject ambient “active tab” targeting. This adds a selection step, but avoids accidental retargeting. Changing later needs a new scope/identity contract and hostile tests.
- **assumed — owner-facing choice:** Treat GET form searches and autosaving edits as submissions; ordinary link/resource reads remain semantically ambiguous. Broad method-based prompting was rejected because it both alarms on analytics and misses data-bearing GETs. Per-site qualification costs ongoing maintenance.
- **assumed — owner-facing choice:** Transfer nominated file bytes rather than grant the extension broad local-file access. This keeps that authority narrow; supporting very large/streaming/directory inputs later requires a different bounded transfer path.
- **assumed — owner-facing choice:** Do not label the prototype safe for the real profile. Rejecting unknown sending paths is more restrictive than the owner's eventual “every feature” goal, but is reversible while the enforcement design is still open. Weakening the promise silently would be hard to repair after real-data use.
