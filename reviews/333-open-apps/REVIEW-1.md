### Blocking findings

1. **A bring-back request can spawn after the app’s window has appeared.** `activate_app` checks for a window and an in-flight start before starting the executable check. When that check finishes, the helper calls `launch()` without checking again. If an app maps a window during the check, a request to bring it back can open a second instance even though the helper has already observed the window. The same race exists when the client request is serviced before compositor events that are already queued. Recheck the window and launch state before spawning on the activation path. Keep deliberate `open_app` independent. 2. **View-history eviction can turn a refused activation into a launch.** A completed refusal loses `activation_pending` and becomes eligible for eviction when a fifth distinct view records a request. If the target window closes and the original view reconnects with the same ID, the helper has forgotten the refusal and can spawn the app. The same eviction can drop an unjoined fallback launch while its process is still starting. Preserve replay protection for these requests within the retry window. 3. **A log write failure can take down the helper.** `ShellLog.handleError()` closes the file before detaching the handler. Closing a buffered file can retry the failed flush and raise again on `ENOSPC` or `EIO`. That exception can escape logging on the serving loop or at startup.
