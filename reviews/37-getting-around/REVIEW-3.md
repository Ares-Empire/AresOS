1. **NIT — “one tick later” overstates what `again()` schedules.**

   Execute a successful swap before the current tick’s `END_SERVER_TICK` callback, with no picture read outstanding. `again()` sets `due`; `step()` can then run the ordinary pass at that same tick’s end. Conversely, an outstanding picture read can postpone it beyond the next tick.

   Consequently, an unrelated renewal or newcomer can change during the same server tick, **after the scoped command has finished**.
