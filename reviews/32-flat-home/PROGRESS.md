## State of the server tests

`mod/dev/build.sh` passed twice in a row (second builder, 2026-11-13): 6 unit tests, "All 45 required tests passed" both times, the second run over the world the first one left behind. How the four red tests were fixed, for whoever touches them again:

1. The test world can be kept between runs, so nothing builds at fixed coordinates any more. `far(helper, x, z)` is the test's own plot (new random coordinates every run) plus an offset; the offsets (3000, 6000, 9000 on x; 8000 on z) keep the hubs apart from the plots and from each other.
2. The mode switch failed because a marked world routes every mode change through `ModeInventories.switchTo`, which refuses a client that cannot acknowledge it. It was not the mock player's `gameMode()` override. `join()` in the test does what `ModeInventoryGameTests.connect` does: unmarked world, plain `ServerPlayer` through `placeNewPlayer`, `ModeInventoryFixtures.registerStateReceiver`, survival; switches go through `ModeInventoryFixtures.switchAndAcknowledge`.
3. The no-mob test runs its control first: mob spawning on (`SPAWN_MOBS`, then `SPAWN_MONSTERS`, because only the second refreshes the level's cached monsters flag), and a slime appeared after 83 and 52 ticks in the two runs. Then `FlatHome.applyRules`, the control's mobs are discarded, and 12000 ticks follow with a survival player at home in a marked world (Live mode). One `helper.onEachTick` callback drives both phases and restores rules, mobs, player and marker on every way out. In a tick callback throw through `helper.fail(...)`: the runner catches `Exception` there, not `AssertionError`.

4. One run in three then failed in the protection test with "An explosion removed a group name". Cause: a chunk loaded in the same tick shows its entities only after the server has run that chunk's queued promotion task, so a text display added to the chunk the build loaded last cannot be looked up by ID yet (it is in the world and is saved). With home at x 15, z 3 inside its chunk the west name is in that last chunk. The test is pinned to this alignment (it failed there every time) and the test's `build()` runs the queued tasks (`level.getChunkSource().pollTask()`); green after that. The game itself is not affected: nothing looks a name up in the tick that built it.

The whole server suite takes about 15 seconds; `build.sh` about 50.

## The plan (decided while reading; nothing here is tested yet)

**Files.** New package `dev.aresos.hub` so nothing collides with packages 33 (`zone/LogoBuilder.java`, `zone/LogoPixels.java`) and 34 (`item/`, `config/`, `shell/`, `catalogue/`, `client/AppsScreen.java`).

- `hub/HubLayout.java`: the constants of HUB.md 3.1 (`SIZE` 12, `DEPTH` 3, `FIRST` 4, `PITCH` 14, `ROW0` 20, `STEP` 14, door columns 5 and 6 / height 3 / depth 2, `EXIT` 6, `ROAD` 5), the look name `flat-1`, the home block (0, 64, 0), and `enum Group { N, E, S, W }` with name, outward vector, right vector, yaw, concrete (block ID as text) and text colour. One method for "outward a, sideways b" → `home + outward × a + right × b`. Keep it free of `Blocks` and registries so a plain JUnit test can load it. No place-to-blocks math for logos (package 36).
- `hub/HubData.java`: `SavedData` with ID `aresos:hub`, which lands in `data/aresos/hub.dat` (the same way `aresos:nether_home` lands in `data/aresos/nether_home.dat`). Shape: `look` ("flat-1"), `numbers` (name → int), `home` (dimension and block), `fixed` = `blocks` (list of `{pos, block}` with the block ID as text) and `names` (the four display UUIDs). Only ever read with `get` (may be null); never `computeIfAbsent`, or an unreadable file would be overwritten by an empty one.
- `hub/FlatHub.java`: builds pad, avenues and names. Every block goes through one `place(level, pos, block)` that sets it only where the untouched grass block still is, and records `{pos, block}`. A position that holds anything else is left alone and not recorded (brief, "If unsure").
- `world/FlatHome.java`: the flat generator settings, `applyRules` (calls `NetherHome.applyRules`, then the two extra rules), and `initialize(server, site)`.

**Home kind.** `aresos-home.properties` keeps `version=1` and gets one extra key `home=flat` for a flat home. A Nether manifest is written exactly as today (no new key), so absent means Nether. Any other value is an invalid manifest (refuse, as today). The home data keeps its format: a flat home is `Site(seed 0, x 0, y 63, z 0, yaw 180)` plus an exact `Home(OVERWORLD, (0.5, 64, 0.5), yaw 180, pitch -8)`. `Site.y` 63 passes `readManifest`'s 33..100 check. `NetherHome` needs one small package-private method to store that pair (its `TYPE` and constructor are private).

**Provisioning.** Same gates as the Nether home, same code path: `createNewWorld` refuses an existing `level.dat` or claim file, `SERVER_STARTING` requires uninitialised level data, the claim file is written with `CREATE_NEW` before the first block. ## Real names in 26.2 (found with `javap`; no sources jar on the laptop)

Jars: `~/.gradle/caches/fabric-loom/minecraftMaven/net/minecraft/minecraft-common-deobf/26.2/minecraft-common-deobf-26.2.jar` and `minecraft-clientonly-deobf`. `~/.local/opt/jdk-25/bin/javap -p -cp <jar> <class>` shows signatures (`-c` for bytecode).

- Rules: `GameRules.ADVANCE_TIME` and `GameRules.ADVANCE_WEATHER` exist, as the design guessed. `rules.set(rule, value, server)`; the server may be null in a test.
- Time is a clock now: `server.clockManager().setTotalTicks(server.registryAccess().lookupOrThrow(Registries.WORLD_CLOCK).getOrThrow(WorldClocks.OVERWORLD), 6000)`; read it with `level.getOverworldClockTime()`. There is no `setDayTime`. `ClockTimeMarkers.NOON` exists for `moveToTimeMarker`.
- Weather: `server.setWeatherParameters(clearTime, rainTime, raining, thundering)`; state in `server.getWeatherData()`.
- World spawn: `server.setRespawnData(LevelData.RespawnData.of(dimension, pos, yaw, pitch))`.
- Flat world: `new FlatLevelGeneratorSettings(Optional<HolderSet<StructureSet>>, Holder<Biome>, lakes).withBiomeAndLayers(layers, overrides, biome)`, `new FlatLayerInfo(height, Block)`, `WorldPresets.createNormalWorldDimensions(registries).replaceOverworldGenerator(registries, new FlatLevelSource(settings))`. `FlatLevelSource.spawnOriginalMobs` is empty. `settings.getLayers()` has one entry per block of height, index 0 at y -64.
- Coloured blocks are collections: `Blocks.CONCRETE.lightBlue()`, `.red()`, `.yellow()`, `.purple()`; there is no `Blocks.RED_CONCRETE`. The block IDs (`minecraft:red_concrete`) are unchanged.
- Entity types are in `EntityTypes` (`EntityTypes.TEXT_DISPLAY`). A display's setters are private, so `FlatHub` creates it from its saved form: `EntityType.create(type, TagValueInput.create(ProblemReporter.DISCARDING, registries, tag), level, EntitySpawnReason.COMMAND)`, with the public tag names `Display.TAG_BILLBOARD`, `TAG_BRIGHTNESS`, `TAG_VIEW_RANGE`, `TAG_TRANSFORMATION`, `Display.TextDisplay.TAG_TEXT`. Read one back in a test with `TagValueOutput.createWithContext(...)`, `entity.saveWithoutId(output)`, `output.buildResult()`.
- `Display.hurtServer` is final and returns false: a group name cannot be hit by anything, in either mode. Nothing had to be added for that.
- Saved data: `server.getDataStorage()` is one `SavedDataStorage` for the save; `get(TYPE)` returns null when missing or unreadable and never calls the type's constructor, `computeIfAbsent` does.
- Server tests: `GameTestServer` uses vanilla's default flat preset (plains, grass at y -61, seed 0, no structures) and leaves the rules at their defaults, so mobs do spawn around test players. `isSingleplayerOwner` is always false there, so `DesktopWorld.isHost` is false for every test player. `helper.makeMockServerPlayerInLevel()` really joins through `placeNewPlayer`. `level.getHeight(...)` returns the minimum y for a chunk that is not loaded (load it first); `level.getBlockState` loads the chunk.
- Explosion mode rule as built: `HubData.protectsFromExplosions(server)` is true unless some player is in creative mode. It does not ask for the host, because of the point above.
- Client: `Screen.rebuildWidgets()` exists; `createFreshLevel(String, LevelSettings, WorldOptions, Function<HolderLookup.Provider, WorldDimensions>, Screen)`.
