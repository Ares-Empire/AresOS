**What the function loader compiles with (point 4).** No sources jar exists for 26.2 here, so this is read from the mapped game jar with `javap -p -c` (`~/.gradle/caches/fabric-loom/minecraftMaven/net/minecraft/minecraft-{common,clientonly}-deobf/26.2/`):

- `ServerFunctionLibrary.reload` compiles every `.mcfunction` with `CommandFunction.fromLines(id, dispatcher, Commands.createCompilationContext(functionCompilationPermissions), lines)`. A macro line (`$…`) keeps that same source (`MacroFunction$MacroEntry.compilationContext`) and is parsed with it when the function is called.
- `functionCompilationPermissions` comes from `ReloadableServerResources.loadResources`. At world load it is the `WorldLoader$InitConfig`'s: `WorldOpenFlows` and `CreateWorldScreen` (singleplayer) pass `LevelBasedPermissionSet.GAMEMASTER`, `GameTestServer` passes `OWNER`, the dedicated `Main` passes `DedicatedServerProperties.functionPermissions`. At `/reload` it is `MinecraftServer.getFunctionCompilationPermissions()`: `IntegratedServer` returns `GAMEMASTER`, `GameTestServer` `OWNER`, `DedicatedServer` the property. The property `function-permission-level` goes through `deserializePermission`: `PermissionLevel.byId` (clamped to 0 to 4), then `LevelBasedPermissionSet.forLevel`, one of the five constants `ALL`, `MODERATOR`, `GAMEMASTER`, `ADMIN`, `OWNER` (default `GAMEMASTER`).
- `PermissionSet.NO_PERMISSIONS` is a separate singleton; none of those five is it, not even level 0's `ALL`. `AppCommands.allowed` compares by identity, so every loader source is refused.
- `Commands.createCompilationContext` is the game's only construction of a `CommandSourceStack` without a server (players, entities, command blocks and minecarts, signs, lecterns, the console, rcon and chase all pass one), and its only callers are `ServerFunctionLibrary` and the client probe `Commands$1.isRestricted`, which passes `NO_PERMISSIONS`. So the exception admits the probe and nothing else in the game. On a dedicated server AresOS registers none of these commands anyway (`includeIntegrated` is false there, and names need `isSingleplayer()`).
- Why the test compiles through `fromLines` instead of a function file in the test datapack: the game test server builds its first command tree with `CommandSelection.DEDICATED`, so AresOS's commands are not on it when its datapack functions load, and such a file would fail as "unknown command" whatever the permissions.

What follows from the brief's rule in point 2: when another mod hangs our node under its own parent and registers there, Brigadier merges into that shared node, which is also our `/open` at the root. A bare `/open` then runs the other mod's command (still host-only, the requirement stays ours), `/open <name>` still opens his programs, and by the ownership rule the node is foreign from then on: AresOS leaves it alone until the next `/reload` or world start installs a fresh one. Stepping aside under the other parent instead would have kept our node untouched, but that is the other mod's tree and the brief settles it as "not our business".
