# Interim security review: document-start injection and native event relay

Reviewed the changing worktree based on `11b396f779473f91070af1caf975fac7f0f2e433` on 2026-11-09. This review is limited to the core extension injection and native-event relay. Implementation files and side-build files were not changed. No local browser or browser profile was accessed. The builder is repairing findings concurrently; this records the source snapshot where they were found, not a verdict on later changes.

## Findings reported immediately

1. **P0 — a held original Event exposes the relay and its cleanup capability.** **Read:** `page.js` dispatches the original event onto its detached relay before the isolated guard decides whether to deliver it. When the guard holds an asking click, it does not redispatch that event onto the intended target. The original event's native `target` consequently remains the relay after the wrapper returns. Page code retains the original Event, so it can obtain `event.target.firstElementChild` and dispatch `aresos-relay-cleanup`. The MAIN cleanup listener sets `enabled=false` and restores the saved native functions. A subsequent form submission bypasses the hold. This contradicts the claim that the relay and cleanup capability are unreachable. The same exposure occurs on unsuccessful transfer/delivery paths. Required regression: hold an asking `dispatchEvent(event)`, attempt cleanup through every retained native event reference, then attempt an unapproved submission; the independent receiver must still show zero arrivals.

2. **P0 — scrubbing the Event only in the report's final cleanup leaves a callback window.** **Read:** after relay transfer, `new Event('aresos-relay-deliver', {cancelable:true})` reads missing WebIDL dictionary members such as `bubbles` and `composed` through the page's `Object.prototype`. A hostile inherited getter can inspect the retained Event's `target` and invoke the cleanup capability before a final target reset runs. The other constructors use ordinary option objects too, and `targetRanges` is an ordinary Array whose iterator can be replaced by page code. Capturing the constructors does not capture these conversion operations. Reset the native target immediately after relay transfer, before constructing another event; eliminate inherited getters and page-controlled iteration during staging. Remove the DOM cleanup capability as defense in depth, keeping restoration on the private CDP path. An immediate reset must preserve native type/bubbles/cancelable and prior cancellation, and must cover failures. The builder's proposed `Event.prototype.initEvent` reset needs native regression evidence for both held and failed delivery, including hostile dictionary getters.

3. **P2 — abort cleanup is not associated with its own stack entry.** **Read:** an inherited getter during the outer request's `InputEvent` construction can invoke a nested wrapped operation. The nested delivery pops its record before invoking page handlers, but the nested MAIN `finally` then sends `aresos-relay-drop`. That listener pops the still-pending outer record. The outer target transfer or original-event transfer is subsequently lost or assigned to a different record. The observed source path tends toward dropped/held input rather than an unapproved send, but violates native compatibility and makes record ownership unreliable. Bind cleanup to a per-request record, and test nested success, nested hold and nested throw. Eliminating all page callbacks during staging reduces the reachable cases but does not itself make the existing unscoped stack operation correct.

## Design findings and evidence limits

**Read:** the new global registration contains only the inert ISOLATED context script. Controlled sessions install an exact extension-script breakpoint, identify the real extension world and matching MAIN context, and initialize guard/reader/wrappers before resuming. DOM node resolution links only the detached relay returned by this initialization. This avoids the previously rejected global MAIN/guard registration.

**Read, primary Chromium source:** normal debugger pauses defer ordinary extension script execution. Cross-world `CustomEvent.detail` uses structured serialization, so an embedded Event cannot serve as a native identity bridge. Receiving the original Event through native dispatch on a shared relay avoids that clone. Sources: [pausable executor](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/blink/renderer/core/frame/pausable_script_executor.cc), [CustomEvent](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/blink/renderer/core/dom/events/custom_event.cc), [cross-world serialization](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/blink/renderer/bindings/core/v8/world_safe_v8_reference.cc).

**Reported by builder, not independently run by this reviewer:** Linux workflow `42688651976` proved exact-URL startup injection in both installation modes; workflow `42691843612` proved original Event identity, CustomEvent payload, cancellation and return-value preservation for the relay probe. Those probes do not establish secrecy after a held/failed dispatch or safety under inherited getters and reentrancy.

No final-head browser matrix, independent receiver attack regression, or repeated full acceptance run was executed by this reviewer. The lifecycle findings in `BUILD-REVIEW-4.md` are separate and remain subject to their own repairs and verification. The findings above must not be marked closed solely because the happy-path relay probe passed.

## Follow-up on the private-verdict redesign

The builder subsequently replaced original-Event transfer with a private request/verdict channel. **Read:** the original Event no longer visits the relay; native click/dispatch is performed in MAIN only after the isolated guard cancels a signal on the detached private control. Form submission remains isolated. A missing guard leaves the signal uncancelled and denies dispatch. Request-number matching scopes abort cleanup. This design removes the direct Event-target disclosure and can satisfy continuation 2: its prohibition covers signals the page can reach, whereas this channel must remain genuinely unreachable. Its permission signal must never also be accepted on the legacy public bridge.

**Additional blocking implementation finding, reported immediately:** the first `options()` helper in that redesign called the page's live `Object.keys(values)` and iterated the returned Array with `for...of`. Page code could replace either function and obtain or modify the actual request/detail and StaticRange initializer objects. Furthermore, assigning a new `detail.request` property on an ordinary object could invoke an inherited page setter with the actual detail object as `this`; ordinary descriptors passed to captured `Object.defineProperty` could invoke inherited `get`/`set` getters. Null-prototype constructor output alone therefore did not remove callbacks or protect target identity. The suggested repair was a captured `Object.setPrototypeOf` applied directly to fresh literal dictionaries, including detail before assignment and property descriptors, plus private iterable/iterator/result objects without page-controlled enumeration. This follow-up requires rereading the actual repaired helper and native hostile-prototype tests before closure.

**Final source reread of this review turn:** the builder chose another valid repair: capture `Object.keys` before page scripts and index its dense result directly; populate null-prototype options and property descriptors; use a private iterable, iterator and iterator-result objects; define the request-number property through the captured native function; and match the request number on target, delivery and abort signals. MAIN also rechecks the native event type and composed document before native dispatch. No original Event is dispatched on the private relay. These changes address the specific source paths described above. I found no remaining relay-specific page-reachable relaxing path in this snapshot. The cleanup event is not independently a violation if the private node remains unreachable; removing it would be defense in depth rather than a condition imposed by continuation 2.

The result is **source findings addressed, native verification pending**, not a green acceptance verdict. Required native cases include held and failed dispatch; forged public relay/cleanup event names; poisoned Object/Array prototypes and inherited dictionary members; nested success/hold/throw; original Event and payload identity; cancellation/return values; and receiver counts before approval, after approval and after replay. No automated test or native browser was run by this reviewer during this review turn.
