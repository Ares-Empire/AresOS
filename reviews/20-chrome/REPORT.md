## PLAN-GAP

**Run/read — blocking popup architecture gap:** the implementation attempted private debugger startup, URL-specific isolated bootstrap breakpoints, recursive flattened `Target.setAutoAttach` and paused OOPIF startup. Four real suites still leave a native `window.open()` child uncontrolled. The final pinned-binary diagnostic independently confirms unavailable browser attachment and no inherited popup preload. This satisfies continue-3's explicit “If no mechanism can put the script in before the page's scripts in Claude tabs only, stop and report” condition.

**Read/inference — why another supported extension design cannot supply this guarantee:** Chromium's new-window wait flag comes from `ShouldWaitForDebuggerInWindowOpen()`, which consults Browser debugger hosts only. Browser sessions require a trusted client, and ordinary extensions do not qualify; the extension trust path names only the one hard-coded privileged profiling extension. Page-level auto-attach covers descendant frame/worker targets, not arbitrary new popup WebContents. Current source was inspected at snapshot `15bbbb7f9dcc96d89ada6f0c2c131edd2ad1b2f0`, not claimed to be the exact build revision of157.0.8103.50: [popup wait implementation](https://chromium.googlesource.com/chromium/src/+/15bbbb7f9dcc96d89ada6f0c2c131edd2ad1b2f0/content/browser/devtools/devtools_instrumentation.cc), [Browser session admission](https://chromium.googlesource.com/chromium/src/+/15bbbb7f9dcc96d89ada6f0c2c131edd2ad1b2f0/content/browser/devtools/browser_devtools_agent_host.cc), [extension debugger restrictions](https://chromium.googlesource.com/chromium/src/+/15bbbb7f9dcc96d89ada6f0c2c131edd2ad1b2f0/chrome/browser/extensions/api/debugger/debugger_api.cc). The real diagnostic supplies the binary evidence alongside that source assessment.

**Read/inference — rejected alternatives:** `Page.windowOpen` and extension creation notifications have no wait/ack handle; late attach/injection/reload can run after the first script. `injectImmediately` explicitly has no pre-load guarantee ([official contract](https://developer.chrome.com/docs/extensions/reference/api/scripting#property-ScriptInjection-injectImmediately)). Registered scripts select URLs, with no controlled-tab/group predicate; registering MAIN for an address changes ordinary duplicate-address tabs. Network interception misses initial blank windows with synchronous opener `document.write()`. Replacing/deferring `window.open` changes synchronous WindowProxy timing and misses native link/form-created windows. A port, browser patch/privileged identity, global JavaScript blocking, page-readable control marker or all-tab MAIN script changes an explicit constraint. None was implemented. This is an inability to guarantee the requirement with the supported platform/constraints, not a claim about every conceivable modified browser.
