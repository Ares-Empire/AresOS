# 53a code review 1

PR #112 needs changes at `a83dc2e3`. The blocking issue is restart reconciliation. The focused security pass found no credential disclosure or way for a view to authenticate as the desktop.

1. **Blocking — A helper restart can permanently record a live app as closed.** If discovery is slow, the helper starts with only the starter catalogue. `adopt_windows()` cannot identify an already-open discovered app, so it writes `closed` to the journal and clears the pending adoption. After discovery finishes, `apps_running` can correctly list the app while replaying the same launch still says `closed`. The view also misses the actual close event. Defer the terminal decision for journal entries marked `discovered` until the first complete catalogue has assigned window owners. The restart test supplies the discovered app up front. Add a case where discovery finishes after the view reconnects. [Reconciliation](../../os/config/usr/libexec/aresos-shell#L3075) · [Restart test](../../os/tests/test_aresos_shell_views.py#L283)

2. **Should-fix — Overlapping launches can report the wrong client’s window state.** If the game and a view both open Terminal, the helper assigns the first window to the oldest pending request for that app. If the second process shows its window first and the first produces none, the first client gets `focused` for the second client’s window, while the successful launch can time out with `no_window`. The event is routed to the client recorded in the journal, but the window was assigned to the wrong launch. For reviewed apps whose windows cannot be correlated to a process, serialize outstanding starts of the same app until the first gets a window or fails. Cover the case where only the second launch produces a window. [Window assignment](../../os/config/usr/libexec/aresos-shell#L3797)

3. **Should-fix — View-only ownership can change desktop focus behavior after an uninstall.** With a 1.0 desktop, a discovered app’s window is unowned by the desktop. If the app is uninstalled while the window remains open, the full-catalogue observer can retain its definition in shared `self.apps`. A later 1.1 desktop then claims that window and can return focus to the game when it closes. Preserve desktop ownership using the desktop tracker and desktop launch history. Keep definitions needed only for view windows or view launches on the view side. Check both an independently opened window and a view-launched one. [Catalogue retention](../../os/config/usr/libexec/aresos-shell#L3403) · [Desktop ownership rules](../../os/config/usr/libexec/aresos-shell#L3985)

4. **Low-harm follow-up — A view can keep a dead house after the first scan.** A view may fetch the unfiltered home while discovery is pending. If the completed catalogue is identical to the starter catalogue, filtering can remove an unknown house without changing the catalogue revision. No event tells the view to fetch again. Emit `home_changed` when deferred filtering removes rows, and cover a first scan with an unchanged revision. Under decision 24, this display issue alone would not justify another fix round. [Deferred filter](../../os/config/usr/libexec/aresos-shell#L3400) · [Event condition](../../os/config/usr/libexec/aresos-shell#L3422)
