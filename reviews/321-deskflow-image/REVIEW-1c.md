1. **BLOCKING — An unrelated program can disable the owner’s shortcuts.** `os/labwc/0002-no-bindings-for-the-capture-layer.patch:197` trusts a client-chosen namespace. 2. **BLOCKING — A session lock can leave capture active with both escape chords disabled.** At `.work/labwc-src/src/src/session-lock.c:340`, lock acquisition requests an ordinary focus clear. Exclusive layer focus rejects it. Labwc then marks the session locked, so the two chords fail the `allow_when_locked` check while ordinary keys can still reach the backend until a lock surface takes focus. 3. **BLOCKING — The previously active window can veto both escape chords.** `os/labwc/0002-no-bindings-for-the-capture-layer.patch:127` still applies `view_inhibits_actions` after accepting a marked binding. Layer focus preserves `active_view`, so a window with `ToggleKeybinds` enabled prevents release and recovery during capture. While the trusted capture layer owns the keyboard, bypass the previous view’s veto for marked bindings. Keep the session-lock check.

4. **BLOCKING — A queued crossing can activate after the switcher or menu opens.** `reviews/321-deskflow-image/PROGRESS.md:246` reasons from the absence of *new* pointer enters. An enter already sent can still produce the backend’s exclusive-focus commit after labwc changes mode. `seat_set_focus_layer` accepts it. Releasing Alt can then finish the switcher and raise the selected laptop window, and a mouse release can execute a menu action before the patched mousebind check. Refuse capture focus outside passthrough mode and end capture before entering a conflicting mode. Test the interval between pointer enter and the exclusive-focus commit.

5. **BLOCKING — A pointer-only capture can outlive its shortcut gate.** `os/input-portal/src/wayland/state.rs:94` allows activation without keyboard focus, and `:1067` ignores keyboard leave for that session. A grabbed layer popup can force keyboard focus elsewhere without clearing the pointer constraint. Laptop shortcuts then run while pointer capture continues. Require exclusive keyboard focus for every capture that promises shortcut suppression, and end it on focus loss regardless of the EIS capabilities granted.

6. **BLOCKING — An input-method grab can receive the Mac’s keys.** At `.work/labwc-src/src/src/input/keyboard.c:658`, an unmarked key still goes through the local input method before delivery to the capture surface. Physical modifier changes also broadcast to unfocused clients at `:185`. Test10 uses a virtual keyboard and omits `MODS` from its local-window check at `os/input-portal/harness/driver.py:1419`. During trusted capture, send unbound keys and modifiers directly to the focused capture client and suppress the unfocused broadcast.

7. **BLOCKING — Test10 does not establish that the recovery terminal opens with a usable keyboard.** `os/input-portal/harness/in-container.sh:72` appends a marker. 8. **BLOCKING — The harness and final-image checks overstate binary identity.** `os/input-portal/harness/run.sh:62` reuses an existing image tag without checking its binaries against the current checkout. `os/ci/image-checks.sh:610` reports both patches from the NEVRA, RPM self-verification, manifest names and two strings.
