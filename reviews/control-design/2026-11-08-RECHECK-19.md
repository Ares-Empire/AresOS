The blocking findings are:

1. **Snapshots do not preserve “every state.”** [CONTROL.md:1490](/Users/pab/AresOS-council-control-layer/docs/design/CONTROL.md:1490): a command can snapshot, wait while the owner saves new work, then delete it. Background processes create the same gap. Hourly thinning also discards versions before 30 days. Nested subvolumes are excluded from parent snapshots, and generation numbers track transactions rather than individual writes. [Btrfs documentation](https://btrfs.readthedocs.io/en/latest/btrfs-subvolume.html) supports those limitations. Define an enforceable write boundary and accurate retention guarantee before offering this choice. Snapshot failure must also stop existing writers; refusing the next command does not achieve that. Free project deletion still awaits the owner’s decision.

2. **The git protection is incomplete.** [CONTROL.md:1508](/Users/pab/AresOS-council-control-layer/docs/design/CONTROL.md:1508): PATH interception does not cover absolute executable paths, embedded libgit2, or other repository-reading tools. Running git through `sudo -u assistant` makes repository ownership match again, allowing planted configuration outside the wrapper. File-manager/editor refusal therefore needs qualification for each actual client. Also, explicit `git -c` overrides `GIT_CONFIG_COUNT`; conditional includes, `core.sshCommand`, and credential helpers remain execution paths. [Git’s configuration reference](https://git-scm.com/docs/git-config) documents these behaviors. `GIT_ATTR_SOURCE` does not eliminate [`.git/info/attributes`](https://git-scm.com/docs/gitattributes). These settings are safe only with unavoidable containment. Require every supported route to be contained or refused, including owner-side routes. Calling editor-triggered scripts “ordinary development” does not resolve the earlier automatic-execution finding.

3. **The mirror cannot guarantee recovery or replace approval.** [CONTROL.md:1542](/Users/pab/AresOS-council-control-layer/docs/design/CONTROL.md:1542): a branch or tag created or updated after one fetch can be deleted before the next. An API request or a script can avoid the recognizable-push hook. The mirror then lacks the lost state. Default/protected-branch rules leave other branches and tags exposed, and a daily warning about missing rules leaves writes enabled. Enforce destructive-operation approval across all refs and protocols, or obtain an explicit, accurately bounded exception. Rulesets must exclude bypass rights for the credential’s actor; GitHub expressly supports [ruleset bypasses](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets).

4. **Added-tool trust still permits unapproved effects.** [CONTROL.md:1691](/Users/pab/AresOS-council-control-layer/docs/design/CONTROL.md:1691): allowing the installing Claude to provide its own review does not establish independent evidence when that session may already be compromised. Review must cover the installed artifact, dependencies, startup and background behavior. An unreviewed server with credentials can send on startup without receiving a tool call; asking on every call cannot prevent that. Require trusted review or enforcement over its actual outgoing operations. A connector marked free can silently change behavior while retaining identical metadata. Require an enforcing adapter or continued per-call approval. Changed-tool handling must reject cached calls at dispatch as well as hide listings.

The should-fix items and judgment calls are:

- The expanded skip-permissions checklist, workstream assignments, shared localhost command, and explicit statement that `CLAUDE.md` enforces nothing address the earlier documentation requests. They remain qualification requirements.
- Registry restrictions, sandboxed preparation and copying-only installation address the fifth blocker’s original routes in principle. Specify exact redirect destinations and package/publisher identities; a typosquat can have a valid hash. For outside sources, separate permission to fetch from subsequent approval of the inspected artifact.
- Connecting through the tool service and retrying an exact URL supplied in the owner’s own message are reasonable choices. Repository ownership handoff substantially changes ordinary git/editor use and needs explicit owner acceptance.
- Stopping writes when snapshots fail is appropriate, but document whether all terminal commands stop. Set measured storage and latency limits: retained build output and metadata consume space. Correct `git fetch --mirror`; use a configured mirror with explicit archival retention.
