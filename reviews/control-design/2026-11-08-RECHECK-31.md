# Design re-check 31: draft 28 (decision 25, Chrome as the light tool)

Reviewer: Codex `gpt-6-astra`, fresh context, 2026-11-08. Reviewed draft 28 at `2e29a7ba`.

Two blocking findings remain:

- **Compose binding still omits relevant content** in the [item rule](/Users/pab/AresOS-design-chrome/docs/design/CONTROL.md:543). A dialog can contain the message body alongside a smaller region containing Send and a recipient field. The smaller region wins; having one editable field avoids refusal, so the body can change throughout approval without detection. Also, a read-only draft preview with no editable fields anywhere passes the refusal condition but contributes no bound content. Bind the complete compose item, including read-only previews, or refuse ambiguous cases. Add both counterexamples to test 3.

- **The third stopped kind is not reliably stopped** by the specified [capture listener](/Users/pab/AresOS-design-chrome/docs/design/CONTROL.md:489). A script can dispatch a non-cancelable click on a labelled Delete link. Stopping propagation prevents handlers, but cannot cancel the link’s default navigation; subsequently resuming it can repeat an action that already happened. This follows the [DOM event rules](https://dom.spec.whatwg.org/#dom-event-preventdefault). Intercept such dispatches before delivery, or explicitly handle them as unsupported rather than reporting them stopped. Test 2 needs this case.

The original submission-kind mismatch is closed: native submit resumes without validation or submit handlers; requestSubmit preserves its path and submitter. The one-use mark and shared allowance must remain consumed across nested handling. A handler can change content or destination before its allowed same-form submission, but that is explicitly accepted post-input page behavior under decision 25, not an exact-payload guarantee.

Both previous should-fix items are addressed at design level: passwords are excluded before extraction, browser-to-extension observations are tested, and test 4 matches confirmation classification. Password qualification should exercise late type changes and show-password transitions inside open/closed shadow roots and cross-origin frames; checking current protection before every value read is essential.

Removing “since its last approved action” fixes that particular dependency, but the replacement item rule leaves the broader binding blocker open. These are design gaps, not merely implementation qualification.
