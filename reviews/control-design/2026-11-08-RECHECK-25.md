# Design re-check 25: draft 24 (decision 24)

Reviewer: Codex `gpt-6-astra`, fresh context, 2026-11-08. Reviewed draft 24 at `a141e8e9`.

Blocking findings:

1. **The promise about hooks is incomplete.** [Section 7](/Users/pab/AresOS-council-control-layer/docs/design/CONTROL.md:1382) establishes precedence over `PreToolUse` hooks, then PLAN generalizes that to every hook. Anthropic separately documents `PermissionRequest` hooks that answer permission requests on the user’s behalf. That leaves an unaddressed path for an ordinary MCP call to execute without the owner answering. S1 tested neither hooks nor managed settings on Linux. Explicitly test `PermissionRequest` auto-approval against the managed ask rule and resolve that interaction before claiming the guarantee. [Anthropic’s hook documentation](https://code.claude.com/docs/en/hooks-guide#auto-approve-specific-permission-prompts)

2. **The optional sandbox’s protection is overstated.** [Section 7](/Users/pab/AresOS-council-control-layer/docs/design/CONTROL.md:1417), section 2’s access table and FEATURES say turning it on prevents terminal commands reaching the service. Enabling it alone still permits unsandboxed retries; in skip-permissions mode those retries run without prompting. Brief 18b’s 127 blocked routes tested the stricter configuration being removed, not this configuration. Keep the sandbox optional, but describe its benefit conditionally and stop implying that enabling it eliminates the accepted bypass. [Anthropic’s sandbox documentation](https://code.claude.com/docs/en/sandboxing#the-unsandboxed-retry-escape-hatch)

- Mark PLAN decision 18’s special WebFetch policy as superseded, matching CONTROL section 10’s statement that normal Claude Code permissions now govern it.
- Scope “passwords and sign-in data belong to a separate system user” to the app credentials held by AresOS. His own `gh` credentials deliberately remain available to normal Claude Code.
