## Blocking

1. **The internet option does not establish a boundary around the laptop or home network.** Disabling published ports controls inbound connections. Denying private address ranges still allows destinations with public addresses that route locally, including the home’s public address if the router reflects traffic back inside. Failed probes against arbitrary addresses or closed ports prove little. Also, dropping `CAP_NET_ADMIN` in the startup process leaves the privileges of a later `podman exec` unspecified. Require a fail-closed egress policy that accounts for host addresses and home routes, and verify it against controlled listening endpoints from every execution path. Run all steps through the verified unprivileged process or enforce equivalent credentials on each entry. Use a clean profile, credential store, proxy configuration and DNS configuration. The fresh Chrome profile protects stored logins, but the network cannot substitute for that protection. Apply the same boundary to image fetches and build steps before enabling them, or keep those phases hosted. `docs/design/TEST-BENCH.md:88`, `docs/design/TEST-BENCH.md:314`, `docs/design/TEST-BENCH.md:469`, `os/input-portal/harness/run.sh:71`.

2. **The watcher can react after the game has already started swapping.** `MemAvailable` and memory pressure are system-wide signals. They give no advance guarantee, and `oom_score_adj` influences eligible kernel victims without deciding which cgroup systemd-oomd kills. Make all laptop-heavy dev entry points share the same lock. Verify that Podman, its helpers and the VMs stay in the capped tree, and stop that tree if the watcher dies. Set a measurable early-stop threshold and check swap growth and responsiveness in the stand-in game, alongside a concurrent-build refusal and a watcher-loss case. State the actual detection and termination delays. Keep the laptop route disabled until those checks pass. `docs/design/TEST-BENCH.md:216`, `docs/design/TEST-BENCH.md:509`, `mod/dev/client-test.sh:74`, `mod/dev/build.sh:25`, `mod/dev/run-hub.sh:119`.

3. **The disk cap and cleanup need enforcement before laptop writes.** The disk table puts evidence outside the store counted by `du`. It also allows the build store, export, builder scratch and new disk to coexist at sizes above 40 GB. Podman temporary storage, sparse disk growth and evidence written between polls can consume the reserve before the watcher reacts. Account for all writes on the relevant filesystem, enforce per-phase limits before issuing writes, and refuse a phase whose bounded peak will not fit. Take the same lock for run, expiry cleanup and `clean`, with the lock outside the directory being deleted. Prove cleanup after interruption and refuse an active store. Settle the shared store location against the worktree rule before use. `docs/design/TEST-BENCH.md:246`, `docs/design/TEST-BENCH.md:603`, `AGENTS.md`, `os/ci/stock_image.py:46`.

4. **Keep changed code and returned evidence out of native execution.** Leave the native test list empty, or bind approvals to the exact reviewed code and everything it executes. For desk evidence, specify a bounded extractor that validates member paths and types before creating files. The cited harness uses `grep -qv` in a pipeline under `pipefail`. An early match can close the pipe, make `tar` fail, and defeat the rejection branch. A returned link in the evidence directory could expose a laptop file when evidence is later read. `docs/design/TEST-BENCH.md:43`, `docs/design/TEST-BENCH.md:88`, `os/tests/test_aresos_shell.py:18`, `os/input-portal/harness/run.sh:19`, `os/input-portal/harness/run.sh:77`.

5. **Build step 1 is feasible as a hosted-only pass once its acceptance contract is corrected.** Define the health check as an authenticated, read-only request to the actual session helper, with launch credentials kept inside the guest. The negative commit must preserve import and `--list` behavior because existing image checks exercise both before the VM boots. Use an explicit no-NIC boot, verify the active auto-login session, and require health again after the new boot ID. Make bench dispatch exclusive with release, rehearsal and published-image switch inputs. Keep a distinct bench tag and scan the plain image’s raw layers with a planted-file negative case. The proposed “any bench file outside `os/ci/`” rule conflicts with the required scripts under `reviews/`. Limit it to image and build inputs. Gate upload on a bounded set of regular evidence files and keep raw guest output out of retained job logs, where an artifact scan cannot help. `docs/design/TEST-BENCH.md:182`, `docs/design/TEST-BENCH.md:508`, `os/ci/image-checks.sh:552`, `os/ci/vm.py:45`, `os/ci/publish.sh:45`, `.github/workflows/os-image.yml:748`, `.github/workflows/os-image.yml:815`.

6. **The local build order still has two impossible gates.** Put the enforced build-network path before the first laptop image build, or make that build hosted until the path exists. Specify how the read-only OCI export becomes an offline install and switch source, where the writable import and scratch live, and how the builder’s inputs arrive before its network is disabled. Step 5 also requires the full worked example, including `tree`, before step 6 implements it. Move that assertion to step 6. `docs/design/TEST-BENCH.md:279`, `docs/design/TEST-BENCH.md:314`, `docs/design/TEST-BENCH.md:510`.

## Known limits to add

- A memory pressure test demonstrates behavior for the load and timing it exercised. A sudden allocation or a stalled watcher can still beat the shutdown. Any owner-facing timing should be a measured result for that test.
- A public destination sees the home connection’s public address, and the configured resolver sees test DNS queries. A clean profile protects local stored credentials. Tests still need synthetic accounts and fixtures for any sign-in.
- Sanitized hardware readings report observable state. A link marked up does not prove connectivity, and unchanged PIDs do not prove the panel or audio recovered. Those observations still belong to the owner.
