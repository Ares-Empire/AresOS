## Blocking

1. **Search can open while the previous app still owns the keyboard.** `os/config/usr/libexec/aresos-shell:4091`, `os/config/usr/libexec/aresos-shell:4105`, `mod/src/client/java/dev/aresos/client/WorldSearchScreen.java:98`. The helper emits `shell_search` as soon as it writes the Wayland activation request. The mod opens the bar without checking window focus. I reproduced the event being emitted while the terminal was still reported active. When 23c enables the shortcut, quick typing can reach that terminal, and Enter can submit its pending input. **Fix** Coordinate the handoff with 23c. Confirm that the mod can accept search, wait for actual keyboard focus, and have the compositor hold input until the bar is ready. Test immediate typing and Enter from a terminal in a private compositor session before enabling the binding.

2. **Super can discard an unsigned book draft.** `mod/src/client/java/dev/aresos/client/WorldSearchScreen.java:110`. Minecraft 26.2 uses a separate `BookSignScreen`. Write pages, click **Sign**, type a title, Tab to **Sign and Close**, then press Super. The focused widget is now a button, so the guard allows the search to replace the editor. Entering the signing screen never saved the pages, and replacing it discards the title and unsaved pages. **Fix** Treat `BookSignScreen` as an editor regardless of widget focus. Add a client regression that moves focus off the title field and checks that the draft survives Super.

## Known limits

- **Should-fix — Super can move focus during a home switch or load.** `os/config/usr/libexec/aresos-shell:4080`, `os/config/usr/libexec/aresos-shell:4100`, `mod/src/client/java/dev/aresos/client/ShellFocusClient.java:64`. The client correctly rejects the bar while the world is unready, but the helper can act on stale readiness before the update arrives. It can also uncover based on the last active handle when no toplevel is currently active. **Fix** Require current client eligibility before moving focus and current compositor activation before uncovering.
- **Should-fix — A transient Wayland write error can end the helper.** `os/config/usr/libexec/aresos-shell:2731`, `os/config/usr/libexec/aresos-shell:4327`. An activation or minimize write can raise `BlockingIOError` on the nonblocking socket. The search path lets it escape the serving loop. I reproduced that exception escaping with a mocked write. **Fix** Queue pending writes with partial-write tracking and use the existing compositor-loss recovery for a disconnected socket.
- **Should-fix — Super can stay disabled after a brief load of the same world.** `mod/src/main/java/dev/aresos/shell/ShellClient.java:662`, `mod/src/main/java/dev/aresos/shell/ShellClient.java:768`, `os/config/usr/libexec/aresos-shell:3650`. If the periodic heartbeat sends `ready: false` during the load, it clears the helper’s search readiness. If the same save becomes ready before `sendWorld` runs, the cached save ID suppresses a fresh `world_ready`, and later true heartbeats leave search disabled. **Fix** Update the writer’s reported readiness whenever it sends a false heartbeat, and test a ready → unready → same-save transition.
- **Should-fix — Enter can launch a result that has scrolled out of sight.** `mod/src/client/java/dev/aresos/client/WorldSearchScreen.java:219`. Scrolling can hide the framed best hit while Enter still opens it. **Fix** Keep the best hit and its Enter label visible while the rest of the list scrolls.
