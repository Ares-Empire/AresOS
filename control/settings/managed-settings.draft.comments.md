# Managed settings draft: provenance and limits

Documentation read 2026-11-07, for **Claude Code 2.1.319**. Anthropic's web documentation is rolling, not a versioned contract. `read in the docs` below means that snapshot, not an observed enforcement result. `checked by running` refers to the named logs from the Linux workflow (run IDs and outcomes in [the report](../../reviews/18b-control-boundary/REPORT.md)). An SRT result is never a claim about Claude Code's private settings resolver.

This is a conservative, non-deployable draft for owner decision 3. `/home/assistant/work` and uid 10001 are explicit image assumptions, not discovered owner paths. The assistant terminal has no internet, no plugins, and a read-only work tree; file tools can still write ordinary work files subject to their permissions. The published runtime keeps `/tmp/claude` writable. No real account, credential or app server is present. No model is used.

## Adjacent controls and deliberate omissions

- `managed-mcp.json`: an **empty** server map is the safe placeholder until brief 18 supplies root-owned proxies. [Exclusive control](https://code.claude.com/docs/en/managed-mcp#exclusive-control-with-managed-mcp-json) also suppresses project/user/plugin servers and CLI config, but admits embedding hosts' in-process SDK servers. **Checked by running**: `mcp-unmanaged-positive`, `mcp-list`, `mcp-add`, `flag-mcp-config`. The launcher runs the CLI directly, accepts no options, and excludes SDK/IDE integration. The full populated proxy set needs integration tests with brief 18.
- `allowManagedMcpServersOnly` is deliberately absent: it restricts the source of allowlist rules; it does not establish the exclusive server set. [Managed MCP policy](https://code.claude.com/docs/en/managed-mcp#policy-based-control-with-allowlists-and-denylists). **Read in the docs**.
- `statusLine`, `subagentStatusLine` and `fileSuggestion` are absent. Managed `allowManagedHooksOnly` narrows all three to managed definitions, so absence here disables lower-scope commands. [Status-line gates](https://code.claude.com/docs/en/settings-reference#disableallhooks). **Read in the docs; needs a model run** with malicious lower-scope values. `disableAllHooks: true` could force status lines off too, but would disable the design's future managed Stop/UserPromptSubmit hooks; it is intentionally not set.
- `apiKeyHelper` is absent. No documented dedicated managed disable key was found in the [credential helper reference](https://code.claude.com/docs/en/settings-reference#apikeyhelper). Omitting it alone is insufficient. The fixed launcher passes `--setting-sources ''` to exclude user/project/local settings, as documented in the [CLI reference](https://code.claude.com/docs/en/cli-reference#cli-flags); it accepts neither environment nor argument overrides. **Checked by running**: fixed arguments/environment recorder. **Needs a model run**: actual effective settings, planted helpers, restart and authentication flows. Cloud/SDK embedding is outside this launcher.
- `allowUnixSockets` is omitted: Linux ignores a path allowlist; enabling `allowAllUnixSockets` removes the filter for every socket. [Socket settings](https://code.claude.com/docs/en/settings-reference#sandbox-network-allowunixsockets). **Read in the docs; checked by running**: named listeners, an abstract listener and missing-helper fallback. Mandatory launcher rejection closes the unfiltered-session case.
- `pluginConfigs.cc-plugin-sec-default@builtin.options.allowManagedModsOnly` is unnecessary while `allowManagedHooksOnly` is true and no plugin is force-enabled. [Mod administration](https://code.claude.com/docs/en/plugins/mods/admin#stop-users-mods) and [hook policy](https://code.claude.com/docs/en/settings-reference#allowmanagedhooksonly) describe mods and monitors (monitors require >=2.1.310). LSP is **not** documented as covered by the hook switch. `enabledPlugins: {}` is not a wildcard deny, and a marketplace policy does not prove a cached LSP was unloaded. The launcher rejects any nonempty installed-plugin registry; **checked by running**: `launcher-preinstalled-plugin`. **Needs a model run**: LSP/monitor/mod cache loading, synced plugins, built-in mods and restart. A managed false entry per installed plugin would be an alternative; this draft ships none.
- `permissions.ask` covers **all** `WebFetch` and `WebSearch` calls. Static permission rules cannot distinguish a URL supplied by the owner from one Claude composed. Asking for both is the conservative enforceable approximation of design section 10, pending the owner's search choice. Do not add `WebFetch(domain:...)` allow rules: those also feed the terminal network list. [Tool-specific rules](https://code.claude.com/docs/en/permissions#tool-specific-permission-rules). **Needs a model run**: redirects, long input, query/URL display and no “always allow” persistence under managed-only rules.
- No guessed send/delete MCP names are included. Brief 18 must generate the real ask list from action definitions and fail if a destructive action is missing. An empty MCP map offers no such actions today.

## Linux write-rule decision

Linux `denyWrite` supports literal paths and a trailing `/**`, **not** recursive exclusions such as `**/.envrc`. See [filesystem wildcard support](https://code.claude.com/docs/en/settings-reference#sandbox-filesystem). The draft therefore denies shell writes to the entire home working tree. The fixed tests include new subfolders so merely enumerating today's repositories cannot hide this gap. Restoring shell writes requires a separately reviewed policy/mechanism; do not replace this deny with ineffective globs. Recursive Read/Edit rules apply to file tools, whose enforcement still needs a model run. [Read/Edit rule syntax](https://code.claude.com/docs/en/permissions#read-and-edit) documents that Edit rules govern file writes too.
