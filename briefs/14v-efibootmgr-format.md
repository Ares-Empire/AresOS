# 14v: The owner tool's firmware parser expects the old efibootmgr format; local fixes only

Follow-up on branch `pkg/14-owner-tools`. Briefs 14 to 14u still apply, with the change below.

## Diagnosis (integrator)

**What happened:**
- Qualification 2 got further than any run before. It completed the offline install, hardware setup, the Windows round trip, tools hot-plug after sign-in, and the Enter resync.
- Then the first real `install` refused with "Linux firmware entry does not uniquely map to target EFI".
- The decoded varstore shows **exactly one** permitted Linux load option: Boot000A "Bazzite", HD partition 1 of the target ESP, `\EFI\fedora\shimx64.efi`. So the firmware is right and the text match is wrong.

**Why:**
- `owner.disk_record` requires `…HD(…GPT,<guid>,…)…File(\EFI\…)` in `efibootmgr -v`.
- Newer efibootmgr/efivar print a file-path node as `/\EFI\fedora\shimx64.efi`, without `File(...)`. Our own retained evidence shows this form from the same formatting library (`HD(2,GPT,…)/\EFI\fedora\shimx64.efi`).
- Every test fed the tool made-up lines in the old form, so none of them could catch this.

## Fix (owner tools plus tests, local only)

1. **Verify the exact format from the pinned sources.** Use the efibootmgr and efivar versions in the pinned Bazzite 44 image (check them from the retained package list or squashfs listing) and their upstream source: how a File node prints, and what `-v` appends (optional data). Record the versions, source links and the exact line grammar.
2. **Rewrite the firmware match as a parser for that grammar**, not a loose regex:
   - Accept a file node printed as `File(\EFI\…)` or as `/\EFI\…`. Keep any other grammar a STOP.
   - Require **exactly one** Boot#### entry whose HD node names the target ESP's GPT GUID (case-insensitive) and whose path is under `\EFI\`.
   - Keep every other check.
3. **On any refusal, save the raw `efibootmgr -v` text** to the private diagnostics record. A mismatch must explain itself next time.
4. **Audit every other parser of tool text output** in the payload against its pinned upstream format, the same way, and fix any made-up fixture. Tests must use upstream-format fixtures (from source or retained real output), never invented ones.
5. **Harness:** when an owner command STOPs in the VM, export that command's saved diagnostics record as evidence, inside the existing checksum-framed protocol, with no secrets.
6. **Artifact classification:** widen the whole-line class to any kernel boot message `[timestamp] Loaded X.509 cert '<name>: <40 hex>'`, which covers "Build time autogenerated kernel key". These are public certificate key identifiers. Record each match per line. Anything else is still a STOP.
7. Regenerate the payload and fingerprint, update every place that states it, and run the local suites, replay and strict checks.
