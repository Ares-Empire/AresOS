# 03: The AresOS image boots in a VM (phase 2, first half of P1)

**Goal:** the first AresOS image exists as code in `os/`, and GitHub Actions proves it works:
- it builds from a pinned Bazzite NVIDIA base
- it boots in a UEFI virtual machine
- it lands in our own minimal session (labwc with a terminal) instead of Bazzite's desktop
- Bazzite's automatic updaters are switched off

**Read first:** `docs/design/OS-BASE.md` §1, §7, §9, §10, Appendix A1 and Appendix E (P1). This package is the image half of P1. The safe installer is the next package.

**In scope:**
1. **`os/Containerfile` and `os/config/`.**
   - Base: `FROM ghcr.io/ublue-os/bazzite-nvidia@sha256:<digest>`. Resolve the current stable digest, verify its signature with Universal Blue's documented method, and record both.
   - Add greetd, labwc and a terminal. greetd auto-logs in an `ares` user into a labwc session that opens a terminal and shows "AresOS". This is a placeholder: no Minecraft yet.
   - Disable the inherited display manager, desktop sessions and autostarts so they never start.
   - Recovery: a labwc key binding opens a terminal, and a separate TTY login works.
2. **Updater exclusions** (A1).
   - Mask the `uupd` units and set rpm-ostreed `AutomaticUpdatePolicy=none`. Disable any bootc auto-update unit.
   - Remove passwordless update grants for the daily user, and disable Flatpak/Homebrew auto-updates and Bazzite update entry points the session could reach.
   - A CI check fails on any enabled unit or timer that looks like an updater and isn't on a reviewed allowlist.
3. **Static safe power defaults for this stage** (§7, B3).
   - No suspend or hibernate: lid and suspend key ignored, sleep targets masked.
   - The power key does a normal clean poweroff for now, since there's no game yet.
   - Record the exact settings.
4. **`os/manifest/`**, generated by CI:
   - base digest and signature identity, and the resulting image digest
   - kernel and NVIDIA driver versions, plus the full package inventory
   - which deployment backend the image actually uses (rpm-ostree or bootc)
5. **CI** (`.github/workflows/os-image.yml`), with pinned action versions:
   - Build the image, turn it into a bootable VM disk (for example with bootc-image-builder or the template's documented method), and boot it in QEMU with UEFI firmware on the runner (KVM if available).
   - Assert that it reaches greetd → labwc session (QEMU screenshot), that the updaters are masked or disabled, that no inherited display manager runs, and that suspend is impossible.
   - Commit the screenshot to `reviews/03-os-image/screenshots/` (download it with `gh`).
6. **Measure and report:** CI minutes per run, runner disk use, image size and VM disk size.

**Out of scope:**
- The installer and target-disk handling (next package).
- Minecraft, Prism, the mod, Plymouth and branding.
- Signing and publishing the image to any registry.
- Anything on the owner's laptop, and real hardware.

**Constraints:**
- **Free GitHub quotas only.**
  - Don't push the image to any registry. Private package storage is only 500 MB, and the image is far bigger.
  - Keep artifacts under about 200 MB, with at most 3 days' retention.
  - Never enable paid runners or change billing.
  - Budget: at most about 6 full CI runs or 400 minutes in total. If the build doesn't fit a standard hosted runner (disk or time), stop and report the numbers and options.
- **Nothing runs on the owner's laptop** except git and gh. No local installs, VMs or containers.
- **No secrets.** None should be needed. If you think one is, stop and report.
- **Distribution later:** recommend in the report how the image should reach a USB SSD in P3 within these limits (for example a public package, release assets, or a local build). That's an owner decision, so don't do it.

**Acceptance:**
- The workflow is green on the PR branch, with a link to the run.
- The committed screenshot shows our labwc session with the terminal.
- `reviews/03-os-image/REPORT.md` covers:
  - measured numbers, digests and the deployment backend
  - the updater inventory and what was disabled
  - judgment calls and the distribution recommendation

**If unsure:** pick the option that changes the least of Bazzite's signed boot, kernel and driver stack.

**Model:** gpt-6.1-sol, xhigh.
