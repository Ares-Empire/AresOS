## Decisions this brief takes

1. **How the plate is told, and the bus question (COMPONENTS.md 4.1 "Not verified", section 8).** The session has a bus: `os/config/usr/bin/aresos-session` wraps labwc in `dbus-run-session`, so every key command inherits `DBUS_SESSION_BUS_ADDRESS`. That bus's daemon starts before labwc; labwc 0.9.6 adds `WAYLAND_DISPLAY` to its activation environment only on real screens (`man labwc`, "SESSION MANAGEMENT": DRM backend, or `LABWC_UPDATE_ACTIVATION_ENV`), so bus activation would work on the laptop but not in a headless test. And starting the program for every press, leaving the rest to GLib's single-instance rule, would start Python and GTK 25 times a second while a key is held. So: no D-Bus service file. The program owns `aresos.indicator` on the session bus (its GApplication app ID) and exports one method at `/aresos/indicator`: `aresos.Indicator.Show(t sequence, s action, s reading)`, that is the sequence number, the key's action word and the read-back, as numbers and fixed words only. The script calls it in the background with an outer deadline, `timeout 0.5 gdbus call --timeout 1 …`, because `gdbus`'s own timeout takes whole seconds. **In order:** the sequence number is taken under the change lock (What to build, 1). The program keeps the highest number it has shown and drops any lower one, so a late or reordered call never puts an older level on the plate. **One cold launch:** only when the call fails because nobody owns the name (not on a timeout), the notifier waits for a launch lock (`flock -w 3` on a file in `$XDG_RUNTIME_DIR`) and calls again. Only if the name is still unowned does it start the program detached, with the request's three values as its arguments (the program shows that first request itself), and wait up to 2 s for the name before it releases the lock. Notifiers that waited on the lock then find the name owned and call it. The program inherits neither lock; GApplication's single instance stays as a backstop. The same route works headless and on the laptop.
2. **The settings file is `~/.config/aresos/settings.json`** (`$XDG_CONFIG_HOME` honoured), not the designed `desktop.json`. The supervisor already keeps a different `~/.local/state/aresos/desktop.json` (its latch and counts, which the guardian reads), and two files of one name invite a wrong-file bug. The file matches its program's name. Update the one line in COMPONENTS.md 4.7 in the same commit. The lead accepted the new name (2026-11-21).
3. **Names and values**, stable from now on (the mod's `set_setting` will send them later): `look` = `A` | `B` | `C` (default `B`), `indicator-place` = `top` | `bottom` (default `top`), `indicator-size` = `small` | `medium` | `large` (default `medium`; scales 2, 3, 4). The file holds a `version` and only the values he set. `get` fills in the rest from the program's defaults, so a later change of a default reaches every setting he never chose.
4. **Effective look:** A for every value in this package. B's files don't exist yet, and C is B plus slider forms. Resolving the setting to a pack folder is one function, the one the B package extends.
5. **No fallback window.** The program draws nothing, logs once and exits before it presents or maps anything when the layer library is missing, when it loads but the compositor offers no layer protocol (`Gtk4LayerShell.is_supported()` false, or a protocol version older than the program needs), or when the window is not a layer surface after the passive setup (What to build, 3). `place_window()` in `aresos-laptop-home` falls back to a normal window on purpose; this program must not. labwc 0.9.6 focuses a newly mapped normal window (`STATE.md`, 53c's known limit), which would take the keyboard from the world.
6. **The "not there" icons are their own state files** in the pack (grey, as `LookA.icon(off=True)` draws them), so the program only copies sprites, and B can bring its own picture for that state.
7. **Brightness touches the backlight only.** Both brightness commands select the backlight class (`brightnessctl --class=backlight`, or the equivalent on the image's version; the builder checks the flag), so a laptop without a backlight never changes an LED. The floor is 1 % of the maximum, as COMPONENTS.md 4.1 says; today's `--min-value=1` is one raw unit. The builder checks whether the image's brightnessctl accepts a percentage for `--min-value`; if not, the script computes the raw floor from the maximum (1 %, rounded up, at least 1). "Brightness / not available here" means no backlight device; "Laptop screen / is off" means a backlight exists but no active output whose connector starts with `eDP`.

## What to build

1. **`aresos-level` (bash, about 50 lines).** For each key, today's command from `os/config/usr/share/aresos/labwc/rc.xml` lines 24 to 29 (`brightnessctl --quiet set 5%+`, `brightnessctl --quiet --min-value=1 set 5%-`, `wpctl set-volume --limit 1.0 @DEFAULT_AUDIO_SINK@ 5%+`, `wpctl set-volume @DEFAULT_AUDIO_SINK@ 5%-`, the two `set-mute … toggle`), by absolute path, with two changes: volume up also unmutes, and brightness selects the backlight only (Decision 7). First the change, then reading the new level, then telling the indicator. Nothing after the change can fail the change or delay it, including a missing, hung or broken indicator, no bus, or a missing layer library. Under a held key several scripts may run at once, and the plate must end on the level after the last press. One change lock (`flock` on a file in `$XDG_RUNTIME_DIR`, waited for at most 1 s, after which the change runs anyway) covers only the device commands and taking the next sequence number from a counter file beside it. It is released before anything else starts, and no child inherits its descriptor. Read-back and the call to the indicator (Decision 1) then run in the background outside the lock, each under its own `timeout`, so a hung read or indicator never delays a later key. When the script starts the program, `LD_PRELOAD` names the layer library (it must load before `libwayland-client`; LAPTOP-HOME.md, "The layer library from Python"). The program drops it from its environment before it starts anything, as `take_token()` in `aresos-laptop-home` does.
2. **`aresos-settings` (Python, about 80 lines)**, as COMPONENTS.md 4.7: it checks the name and value, writes the whole file at once (a temporary file in the same folder, flushed, renamed into place) and creates the folder if missing. No file means the defaults; a broken file or value means the defaults and one journal line. `set indicator-place` or `set indicator-size` then runs `aresos-level` to show the plate once, with the current volume. `set look` only writes, since the sync step is the B package's. The defaults live here and nowhere else: the indicator gets the settings from this program's code (`get`'s JSON, or the program loaded as a module) at the start of each showing and when told by `set`.
3. **`aresos-indicator` (Python, about 300 to 400 lines).** A port of `indicator()` and the drawing parts of `LookA` in `reviews/312-component-study/tools/look.py`: the layout asks the pack for every size and part, and `place()` gives the screen margins (8 units from the top; for `bottom`, 64 units clear above the bottom edge), in the indicator's own scale. What it must not get wrong:
   - **Overlay layer**, keyboard mode none, an empty input region set before the first map, and exclusive zone −1, so it never reserves space and no window ever moves when it shows. Namespace `aresos-indicator`.
   - **Cairo only:** `GDK_DISABLE=gl,vulkan` and `GSK_RENDERER=cairo`, as `load_gui()` in `aresos-laptop-home` does, so a key press never wakes the NVIDIA chip.
   - **Screens:** volume and microphone without a named output (labwc picks the screen); brightness on the output whose connector starts with `eDP`, or "Laptop screen / is off" on the pointer's screen when there is none (no backlight at all is "not available here", Decision 7). A new showing makes a new surface, so it lands on the screen the pointer is on now. Headless outputs are `HEADLESS-n`, so one test-only variable may name the laptop's output.
   - **Text** through Pango (missing letters fall back), never as markup (a Bluetooth name is someone else's text). Jersey 10 at an absolute pixel size (18⅔ px per unit of scale: 37⅓, 56, 74⅔), with the capitals' top on a whole unit. Fix the font options in the program (antialiasing off, no hinting, no subpixel colour) so the owner's fontconfig can't change them. So every text pixel is the text's pack colour: Jersey 10 lands on whole pixels at these sizes (COMPONENTS.md section 2) and draws exactly the study's letters, so a letter that differs from the study's glyph mask means a placement bug, and a fallback letter from another font draws hard-edged, never grey.
   - **Timing** as 4.1: gone at once 1.5 s after the last key event, one plate only, the last step flashing at 100 %. Each showing loads the pack and the settings again. It exits after a minute without a key; a test-only variable may shorten that.
   - **The output's name** ("Speakers", "Headphones", "HDMI", a Bluetooth name cut to fit, else "Volume") comes from PipeWire's properties. The builder finds which ones, and the program looks it up itself.
4. **The look pack**, from the study's art, never drawn or edited by hand and never from the game. A generator `os/look/make_pack.py` imports `look.py`'s maps (`PALETTE`, `A_SPRITES`, `a_step`), so the art keeps one copy. It writes `look.json` (colour roles, the sizes `LookA` keeps, one entry per sprite with file, size, nine-slice insets and states) and `sprites/`: `plate`, `slot`, the five `step-*`, `sun`, `speaker`, `speaker-muted`, `microphone`, `microphone-off`, and the grey state of each icon. Nothing else: buttons, the frame's images, the pictograms and the Home picture come with their packages. A unit test regenerates the pack and compares its pixels with the committed files (it needs Pillow, like the study's tools, and says so when it skips). No new art is expected; if a part is missing, type it as a pixel map in `look.py`'s style, never traced.
5. **The image.** The six `rc.xml` lines call `/usr/libexec/aresos-level <action>`, nothing else in `rc.xml` changes (`<theme>` and Ares-Crown stay), and the image checks and tests that know today's lines change **in the same commit**: the six-keys block in `os/ci/image-checks.sh` (about lines 564 to 585, its pass line included; add `gdbus` to its `command -v` loop) and `test_brightness_volume_and_mic_keys_use_tools_in_the_image` in `os/tests/test_everyday_account.py`. Its exact command strings move into `test_aresos_level.py` as the script's commands (brightness as Decision 7 says). Step 1's image check asserts the six exact bindings. In step 2, once the indicator exists, add `aresos-level` to the startup-commands file list (about line 419), so every path it runs must exist; before then that scan would fail on the indicator's path. New image checks: the three programs exist root-owned with mode 755; `aresos-indicator`'s GTK loader works as the everyday account, the way the cover's check works, with `Gtk4LayerShell` required; Jersey 10's SHA-256, its licence text, and `fc-match 'Jersey 10'` finding it (`build.sh configure` already rebuilds the font cache); the pack's file list and one SHA-256 over it, pinned as Ares-Crown's check pins its theme. README's licence list gets Jersey 10.
6. **`linux-aresos` reads it first.** The lead sends `linux-aresos` the six lines and the check changes, and merges only after its OK.

## The bar

Safe the way a good command-line tool or MCP is, not every edge case (decision 24, `docs/design/CONTROL.md`, "The bar"). Fix real harm: a key that stops changing its level; the indicator taking the keyboard or the pointer, above all from the world's pointer lock; anything of the game's art or font in the repo or the image; a change to the owner's running session or system (on his system: no install to `/usr`, no labwc reload, no real `brightnessctl` or `wpctl`, nothing with `sudo`, never his `~/.config/aresos/` or `~/.local/state/aresos/`). Low-harm edge cases go into `reviews/320-indicator/KNOWN-LIMITS.md` with the reason, not into another fix round. The board's limits for desktop pieces hold: it binds no key and never Super alone (Super is the search over the world); it leaves the laptop home's paths and `aresos-shell`'s focus-return rules alone; own pixel art only, never Mojang's, in a style the mod can copy later; Ares-Crown's checksum pin is the frame package's.
